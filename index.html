Code proves a path, not a product. An interactive guide through the complete handwritten PyTorch transformer pipeline: one architecture, cross-entropy pre-training, SFT instruction-tuning, and RL alignment (PPO, DPO, GRPO) to interactive chat.

STAGE 01 PIPELINE & TOKENIZATION

The Source-Line Pipeline

The whole journey is one concept repeated: turn raw text into integers, predict the next token with causal masking, then refine data and loss objectives through SFT, DPO, and GRPO until the model converges on chat.

Stage Progression

From The Pile to Aligned Chat

Every stage in this repository is implemented in pure PyTorch without external wrappers like Hugging Face transformers, trl, or peft.

τ : text → tokens → Transformer → CE → base → SFT → {PPO, DPO} → GRPO → chat

Key takeaway: Notice how each downstream stage changes the data distribution or loss formulation, while the underlying Transformer backbone weights and topology remain strictly identical.

    STAGE 02 ARCHITECTURE & PARAMETERS

    Transformer Anatomy & Parameter Math

    A clean decoder-only causal Transformer written in raw PyTorch. Inspect the exact linear algebra parameter formula, test custom configurations (from 13M to 3B+), view the five modular source files, and budget GPU VRAM requirements.

    Closed-Form Parameter Math

    Analeza: Analytical Parameter Counting

    Write the model as token and positional embeddings, plus N identical transformer blocks split into Multi-Head Attention and MLP sub-layers. Summing every weight tensor yields a single closed-form formula for total parameters:

    τ(d, N, T, V) = Vd + Td + N(12d² + 10d) + 2d + Vd + V

    Where d = embedding dimension, N = layer blocks, T = context length (256–2048), and V = vocabulary size (50 304). Untied LM projection head.

    Did you know? In standard causal LLMs, the feedforward MLP uses an intermediate expansion of 4× embedding dimension (4d), accounting for ~66% of total block parameters.

          STAGE 03
          PRETRAINING & GENERATION
        
    
        
    Next-Token Cross-Entropy Loss & Inference
    
        
    
          Every epoch of pretraining optimizes the exact same objective: compute cross-entropy on next-token predictions, calculate backward gradients, and descend. Scrub the 77M training trajectory and inspect actual model generations across checkpoints.
        
    
      
    

      
    
        
    
          
    The Core Pretraining Objective
    
          
    Causal Language Modeling Descent
    
          
    
            During pretraining, tokens are processed autoregressively. Each position attends only to preceding tokens via the lower-triangular causal mask. The model predicts the probability distribution over all 50 304 vocabulary tokens:
          
    
          
    
            L = CrossEntropy(softmax(logits), yt+1)
          
    
          
    
            In the 77 million parameter training run on The Pile, loss drops rapidly from initial random entropy (11.14) down to 3.73 train (3.76 validation) over 2 000 steps.
          
    
          
    
            Training insight: Cross-entropy loss of ~3.7 corresponds to a perplexity of ~40 on diverse internet text, enough for the model to learn grammar, spelling, facts, and code syntax from scratch.

          STAGE 04
          POST-TRAINING ALIGNMENT
        
    
        
    Turning a Base Model into an Assistant
    
        
    
          After pretraining, the neural weights are frozen or fine-tuned with new objectives. Discover five classic and frontier post-training methods implemented in pure PyTorch on the exact same transformer backbone.
        
    
      
    

      
    
        
    
          
    
            
    
              Supervised
              
    Stage 1
    
            
    
            
    SFT: Supervised Fine-Tuning
    
            
    ce = (CE(logits, y) * mask).sum() / mask.sum()
    
            
    Instruction-answer pairs (Alpaca, Dolly). Loss masks prompt tokens so gradients backpropagate solely through assistant responses.
    
          
    

          
    
            
    
              Reward Scoring
              
    Stage 2
    
            
    
            
    RM: Reward Modeling
    
            
    L = −log σ(r(chosen) − r(rejected))
    
            
    Bradley-Terry ranking on chosen/rejected preference completions. Replaces LM head with a scalar linear layer to score candidate completions.
    
          
    

          
    
            
    
              Direct RL
              
    Stage 3
    
            
    
            
    DPO / ORPO / KTO
    
            
    −log σ(β (π log-ratio − π_ref log-ratio))
    
            
    Implicit reward formulation directly optimizes policy on preference pairs without separate reward model training or unstable online rollouts.
    
          
    

          
    
            
    
              Actor-Critic
              
    Stage 4
    
            
    
            
    PPO: Proximal Policy RL
    
            
    −min(ratio · A, clip(ratio, 1±ε) · A)
    
            
    Classic reinforcement learning from human feedback (RLHF). Trains actor policy and critic value network with Generalized Advantage Estimation.
    
          
    

          
    
            
    
              Reasoning RL
              
    Stage 5
    
            
    
            
    GRPO: Group Relative RL
    
            
    Ai = (ri − mean(G)) / (std(G) + ε)
    
            
    DeepSeekMath/R1-style alignment. Samples groups of candidate answers per prompt, normalizes relative advantage, and drops the critic network entirely.

      Rigorous Objective Testing
      
          
      Greedy Generation & Verifiable Rewards
      
          
      
            In mathematical benchmarks like GSM8K, subjective reward models are replaced with deterministic verifiers. The test script scripts/eval_post_training.py evaluates answers across all alignment stages:
          
      
          
        
            
      • 
              1.2
              Gold + Format: Correct numeric answer enclosed in <answer> tags.
            
        • 
            
      • 
              1.0
              Gold Only: Correct numeric answer, but missing required tags.
            
        • 
            
      • 
              0.2
              Format Bonus: Valid XML tags, but incorrect calculation.
            
        • 
            
      • 
              0.0
              Total Miss: Neither valid formatting nor correct answer.
            
        • 
          
      
          
      
            The RLVR Revolution: Rule-based verifiers eliminate reward hacking, allowing GRPO to achieve strong reasoning gains on small models without large human feedback datasets.

          STAGE 06
          THEORY & PHILOSOPHY
        
      
        
      The Mathematics & Meaning of τ
      
        
      
          Why training from scratch is about understanding the mathematical invariance of the architecture, free from opaque abstraction layers or commercial lock-in.
        
      
      
      

      
      
        
      
          
      Form Over Product
      
          
      Fit, Not Forced
      
          
      
            A substitution test proves that the core arithmetic does not depend on marketing buzzwords. Replace the code with any external library wrapper, and the matrix multiplications compute identically.
          
      
          
      
            Yet "from scratch" carries enduring educational significance: one clean architecture, built of transparent files, trained on open data, and aligned through loss functions anyone can read and inspect.
          
      
          
      
            The Core Tenet: Mastery comes from writing every projection, normalization, attention mask, and reward function yourself before delegating to automation.
          
      
        
      

        
      
          
      
            
      
              Formal Invariant
              
      The τ System Definition
      
            
      
          
      
          
      
            τ = (MLP, Head, Blockᴺ, CE, SFT → {DPO, PPO, GRPO})
          
      
          
      
            From-scratch, in this reading, names τ. Existence as a commercial hosted service is not the goal of this project; understanding the immutable form is.
          
      

          
      
            
      
              
      PROVED
      
              
      T1–T9, closed-form parameter math, CE barrier, unique sink at chat
      
            
      
            
      
              
      STIPULATED
      
              
      r50k_base tokenizer, ReLU activations, untied LM head, pre-LayerNorm
      
            
      
            
      
              
      EMPIRICAL
      
              
      13M / 77M / 406M / 3B scaling runs, GSM8K reward table, RM accuracy 0.574
      
            
      
            
      
              
      EXCLUDED
      
              
      Black-box library wrappers (transformers, trl, peft)
